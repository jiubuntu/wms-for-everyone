## 아키텍처

- DDD 기반 4계층 구조를 도메인마다 공통 적용: `ui` / `application` / `domain` / `infrastructure`
- 업무 도메인은 `com.jiubuntu.wms.biz` 하위에 도메인별로 분리 (`global`과 구분)
- Service/Validator는 자기 도메인의 Repository만 직접 참조 — 다른 도메인 데이터가 필요하면 해당 도메인의 Service를 거침
- 도메인 간 Service 의존은 한 방향으로만 허용 (순환 참조 방지). 여러 도메인을 조합하는 유스케이스는 오케스트레이션하는 쪽만 다른 도메인 Service에 의존
- 관리자(시스템관리자) 전용 API는 `com.jiubuntu.wms.admin` 최상위 패키지로 분리, 도메인별로 `ui` / `application` 계층만 두고 `application`은 각 `biz` 도메인의 `application`(Service)을 참조해 비즈니스 로직을 공유

## 핵심 도메인

| 도메인 | 설명 |
|--------|------|
| 사용자 | 회원가입 / 로그인 / 인증 |
| 공통 코드 | 카테고리, 보관 유형 등 시스템 코드 관리 |
| 상품 | SKU 기반 상품 관리, 단위 변환, LOT 관리 |
| 창고 | 물리적 창고 관리 |
| 위치 | 창고 내 세부 위치 (구역-행-열-단) |
| 재고 | 위치별 상품 수량 실시간 관리 |
| 입고 | 상품 입고 처리 플로우 |
| 출고 | 상품 출고 처리 플로우 |
| 재고 이동 | 창고 내 위치 간 이동 |

## 주요 정책 및 의사결정

- **권한 체계**: 시스템관리자 / 기업관리자 / 창고관리자 / 작업자 4단계 고정 역할
  - 기업관리자는 자유 가입 후 시스템관리자 승인으로 활성화
  - 창고관리자·작업자는 자유 가입 불가, 상위 관리자가 계정 발급 + 창고 배정
- **데이터 격리**: 기업별 멀티테넌시, 타 기업 데이터 접근 불가
- **삭제 방식**: soft delete(`active` 플래그) 전 테이블 공통 적용
- **감사 추적**: `created_at/updated_at/created_by/updated_by` 전 테이블 공통, 재고 이력은 수정·삭제 불가 원장으로 별도 관리
- **보안**: 로그인 5회 연속 실패 시 계정 30분 잠금, Refresh Token은 HttpOnly/Secure/SameSite 쿠키로 관리
- **상품/재고**: 상품 단위는 기본+보조 단위 변환 지원, LOT 관리 선택 적용, 재고는 위치 단위로 실시간 관리하며 직접 수정 불가(입출고/이동/조정을 통해서만 반영)

## 진행 현황

- **완료**: 인증/인가(JWT, 역할 기반 접근 제어), 기업 가입·승인 플로우(S3 파일 업로드 포함), 관리자 기초 화면(대시보드/기업 승인 관리), API 문서화(Swagger)
- **설계 완료 · 개발 예정**: 상품/창고/위치 마스터 데이터, 입고/출고/재고 이동/재고 이력 등 핵심 창고관리 도메인
